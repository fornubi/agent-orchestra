01 / The Problem

Claims vs. Evidence

Autonomous coding agents speak in persuasive, confident prose. In CI/CD pipelines, automated delegators, and multi-agent loops, an agent's statement that a task is complete is not evidence.

The Phantom Edit

Deceptive Exit 0

The agent outputs a detailed conversational recap explaining how it redesigned a module and fixed all bugs. But due to tool invocation mistakes or read-only execution modes, no files were written to disk. The underlying CLI exits with status code 0, silently passing unnoticed in conventional build scripts.

Unnoticed Mode and Permission Walls

Silent Failure

Certain provider modes quietly refuse operations rather than crashing. For example, Google Antigravity's --exec-mode accept-edits has been observed to silently do nothing when a task requires creating brand new files. Without a before-and-after filesystem diff, downstream scripts cannot detect that the task was abandoned.

Mid-Run Quota and Auth Halts

Incomplete State

API rate limits, token exhaustion, and session expiry often trigger late in an agent's reasoning loop. If no files were altered, orchestra catches the failure pattern and halts with exit code 5, ensuring your pipeline does not continue against an untouched repository.

02 / How It Works

Deterministic Verification Pipeline

orchestra.py is a single Python file with no dependencies. It wraps external coding agents in a six-stage audit sequence:

01

Provider Flag Synthesis

Refuses the calling agent and any agent already in the delegation chain, then translates universal options into provider-specific syntax for claude, agy, pi, or opencode. On Windows, multi-line prompts are automatically staged as files to prevent cmd.exe from cutting arguments at the first newline.

02

Baseline Snapshot

Traverses --workdir and creates an in-memory SHA-1 digest for every file up to 50 MB (larger files are tracked by size). Automatically skips VCS directories (.git), dependencies (node_modules), caches (__pycache__), and agent state.

03

Supervised Process Run

Executes the agent non-interactively with a configurable --timeout (default: 600s). On timeout it kills the agent and its child processes: with taskkill on Windows, and through a process group on macOS and Linux.

04

Post-Run Diff

Takes a second snapshot of --workdir and computes the exact difference: files created, modified, and deleted. If --expect-changes was requested and no files changed, orchestra halts with exit code 3.

05

Audit Record

Writes run parameters, prompt, exit code, duration, diff summary, and the trailing 200 lines of console output to state/logs/<timestamp>-<provider>.log (retaining the 50 newest runs).

06

Verification & Exit Signal

Runs the command specified by --verify "<cmd>" (e.g., npm test or pytest) inside the working directory, then emits an explicit exit code. If the verification command fails or times out, that code is 4.

03 / Exit Codes

Deterministic Status Signals

Automated workflows should branch on status codes, not parse natural language strings. orchestra maps execution states into explicit numbers:

Code Status Trigger Condition
0 Success Agent exited 0, expected changes occurred, and --verify command passed (if specified).
N Agent Error The underlying agent CLI exited with its own non-zero code N.
3 Silent Failure Agent exited 0 with no stdout output and no file changes, OR --expect-changes was set and no files changed.
4 Verification Failed The --verify "<cmd>" command returned a non-zero exit code or timed out.
5 Quota / Auth Limit A known quota, billing, rate limit, or auth error phrase was detected and no files were modified.
6 Refused The provider is the calling agent or already in the delegation chain. It was not started.
124 Timeout Execution exceeded --timeout seconds. The agent and its child processes were killed.
Quota Warning Behavior: If a quota or billing phrase appears in the agent output but files did change on disk, orchestra outputs a warning to stderr and proceeds with normal exit code evaluation.
04 / Supported Providers

Supported Agent Engines

Provider CLIs must be installed and authenticated separately. orchestra operates as an out-of-process harness over their non-interactive interfaces. An agent can never delegate to itself: python orchestra.py providers leaves out the caller, and running it exits 6. To delegate from Claude Code, Codex, Gemini CLI, or OpenCode, run python install.py (or python3) in your clone to install the included skill.

Claude Code

claude -p

Receives the prompt on stdin. Runs in acceptEdits mode by default, so it edits files but runs no shell commands; use --verify for tests.

--model <name> --effort {low..max} --exec-mode {accept-edits,auto,plan} --output {text,json}

Google Antigravity

agy -p "<prompt>"

Supports reasoning effort control, execution modes, and permission auto-approval.

--effort {low..max} --exec-mode {accept-edits,auto,plan} --dangerous
Caveat: --exec-mode accept-edits has been observed to take no action when a task requires creating brand new files.

Pi Agent Harness

pi -p "<prompt>"

Supports model selection, API provider targeting, JSON mode, and ephemeral sessions. Multi-line prompts on Windows are attached as temporary markdown files.

--model <id> --provider <name> --output {text,json} --approve --no-session

OpenCode

opencode run "<prompt>"

Runs tasks via OpenCode's non-interactive execution mode. Defaults to invoking an agent named orchestra.

--agent <name> --output {text,json} --auto
Requirement: Defaults to --agent orchestra. Running python install.py installs this agent to ~/.config/opencode/agents/orchestra.md. It can edit files inside the working directory but has no shell.

Freebuff

Not Supported

freebuff is strictly an interactive terminal user interface (TUI) and does not provide a non-interactive command line interface. It cannot be automated with orchestra.
